### 3.2 dither 固定证据

- Python `dither=1.0`，同段音频 3 次 `extract_fbank`：两两 `max|Δ|` = ['0.322', '0.783', '0.553']（特征本身随机抖动）
- Python `dither=0`，同段音频 3 次 `extract_fbank`：`max|Δ| = 0`（可复现）
- Python `dither=0`（基线快照已固定为 0），5 次 `AutoModel.generate` 时间戳 `max|Δ| = 0 ms`
- **FunASR 行为发现**：`AutoModel.generate` 每次调用都会执行 `_reset_runtime_configs()`，用构造时的 `copy.deepcopy` 基线覆盖 `auto.kwargs`，因此运行时设置 `frontend.dither = 0` 会被丢弃。直接跑 `generate`（引擎现状）时前端仍是 配置默认 `dither=1.0`：5 次时间戳两两 `max|Δ| = 20 ms`（非确定性）；与固定 dither=0 对比 `max|Δ| = 20 ms`。导出脚本通过改写 `auto._base_kwargs_map` 里的前端快照把整条链路固定为 dither=0。
- ONNX（dither 恒为 0）vs Python dither=0（端到端时间戳）：见 §4.2。

## 6. 已知限制与风险

- **许可**：`funasr/fa-zh` 权重为 **Apache-2.0**（上游 ModelScope 模型卡已核实，见 `docs/LICENSE_AUDIT.md`）；权重/ONNX 不提交 Git，仅作为 Release 资产分发。
- **量化与歌声**：INT8 在真实歌声行上 `max|Δ|` 见 §4.3；歌声音高/混音与朗读差异大，量化误差高于朗读；KTV 场景建议端上保留 FP32 回退。
- **`token_num` 敏感**：CIF 上采样头用 `token_num / sum(alphas)` 归一化，token 数与音频不匹配时会重归一化（§2.4 步骤 2）；INT8 与 FP32 在该路径上的峰值数差异见 §4.4。
- **内存**：桌面进程峰值 RSS 见 §4.5（含 ORT runtime 与音频缓冲）；Android 端需用 ORT-Mobile + 动态 `input_values` 维度，12 s 窗口按实测预留。
- **桌面 ≠ 设备**：以上全部为 x86 CPU 单线程参考值；ARM 上 INT8 通常更快，但需在真机上复测 §4.4/§4.5。
- **前端**：本机无 torchaudio，FunASR 走 kaldi-native-fbank；若日后环境出现 torchaudio，需按任务书 §2.2 重新核对边界帧。

## 7. 未做/做不了的部分（如实说明）

- **真实 FFT 不可导出**：`aten::fft_rfft` 在 opset 17 无法导出（`torch.onnx.errors.UnsupportedOperatorError`），改用把 Hamming 窗折进去的 DFT 矩阵乘（256×400，float32）。与 kaldi-native-fbank 的逐值 `max|Δ| = 0.000106543`（§3.1）。
- **`cif_wo_hidden` 的顺序循环不可动态轨迹**：官方实现对时间轴做 Python 循环，追踪导出会把 T3 固定死。改为与渐增器完全等价的闭式（`cumsum`/`floor`），逐值 `max|Δ| = 12`，峰值数不一致样本 2，端到端时间戳不一致样本 2。
- **SANM 编码器 mask 省略**：batch=1 无 padding 时 FunASR 传入的 mask 全为 1，在图里直接省略（数学上恒等）；因此图不支持 batch>1 或带 padding 的批量输入（契约本就是 `[1, N]`）。
- 未在真机（Android/ARM）上跑过；未做 XNNPACK/NNAPI EP 验证；未评估 ONNX Runtime Mobile 的二进制裁剪。
- `fleurs_zh_sample2.wav` 本地无转写文本，仅用于前端等价性（不参与时间戳比对）。
- 测试向量只用了仓库内可用的 FLEURS/TTS 素材；`Test/` 中第三方歌曲仅作评估输入，歌词文本未写入任何交付文件（见 `_work/cases.json`，该目录不提交）。
