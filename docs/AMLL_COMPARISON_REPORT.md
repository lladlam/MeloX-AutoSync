# AMLL TTML 对照验收（暂定，基准 `ad1d26c`）

## 结论先读

四份官方 TTML 均成功解析，主歌词带时间单元数与预期完全一致：**429 / 485 / 434 / 469**。
基于文本顺序匹配，本地 V1.0 production 输出得到真实计算的暂定误差；但本地 MP3 与 TTML
的版本关系**尚未经人工听音确认**。四份音频的可用元数据没有本地 ISRC，前三首/后两首的
TTML 结束时间与 MP3 时长也存在差距。因此下表是**零偏移、未校正的候选对比，不是最终同版
验收精度**；版本状态确认前，不能将其当作 AMLL 同版准确率或用来作发布门槛结论。

本轮**未修改任何 AutoSync 声学模型、对齐算法、阈值或路由代码**。代码仅新增独立评测器与测试。

## 解析器核对与人声角色

`benchmarks/amll_ttml_eval.py` 独立解析 TTML；识别 `<p>`、带 begin/end 的 `<span>`、
translation/romanization 排除、`ttm:role="x-bg"`、`amll:empty-beat` 属性/元素、agent、
实体和 TTML clock/秒/毫秒/帧/tick 时间。空白/标点仅做 NFKC、casefold 和不计文本匹配，
时间匹配本身不参与文本匹配；`seq` 容器 fail-closed。合成 TTML 测试覆盖命名空间、嵌套
背景声、实体、Unicode、frame/tick 等时间格式与空拍标注。

| 歌曲 | p 行 | 主歌词带时单元 | 显式 x-bg 单元 | 非主唱 agent 的主轨单元³ |
|---|---:|---:|---:|---:|
| DAMIDAMI | 50 | 429 | 0 | 56 |
| 预言 Prophecy | 58 | 485 | 62 | 47 |
| 不安灵魂收容所 | 54 | 434 | 0 | 142 |
| 提瓦特民谣 | 53 | 469 | 68 | 117 |

³ 参考文件的主歌词区还使用多个 `ttm:agent`，不同 agent 之间发生重叠（跨 agent 重叠
对数依次 17、38、18、0）。这些 agent 均保留计数；AutoSync 没有 singer diarization，也没有
 AMLL 独立和声时间轴，故逐 agent 绝对准确性及 x-bg **没有可比预测**（`n=0`），不能把
合并的主歌词得分宣称为某个特定演唱者的准确率。《预言》解析出 31 个 x-bg 单元越过父 p
的行时间范围；该轨已分离，不进入主歌词误差。主轨文本时间单元数与任务给定数相符，未
调整计数以迎合期望。

## AutoSync 预测与精度口径

- 输入是基准 `ad1d26c` 的**真实 CLI 重新推理**：`production`、`--route-lines`；四份原始结果
  含模型 unit、source、quality、force_fallback、行路由。旧结果曾被报告净化脚本替换成
  `<redacted>`，评测器会拒绝这种文件，故没有拿被净化的旧结果参与比较。
- 推理清单 `experiments/amll_results/inference_manifest.json` 记录当前源码提交、核心源码未变、
  Python/依赖、模型文件哈希、本地音频/LRC SHA-256 与完整命令。所用模型为
  `facebook/wav2vec2-base-960h`（EN）、`funasr/fa-zh`（ZH）；每行路由在本地原始 JSON。
- `model_generated_units` 与 production 接受 units 分开记账；模型生成却被 player timeline
  拒绝的预测只进入 rejected diagnostic 分组；heuristic/source=failed 都不会冒充模型输出。
- 四首的 `quality_gate.enabled=false`，所有 model units 均为 `not_assessed`。因此 `reliable`
  误放率是 **N/A（没有 reliable 判定样本）**，不是 0%；production word 模式只表示 player 接受。
- AMLL 的主唱/背景人声分开计数，但因为 AutoSync 没有独立背景声预测，背景人声准确率为 N/A。
- AMLL 中不同 agent 的时间重叠和 LRC/AMLL 文本表述差异可能影响文本可比性；所有未匹配行、
  单元原因、误差最大的前 10 起止样本及逐行偏差仅存本地 `comparison_detailed.json`，不把
  猜测原因写成已证实根因。
- 区间跨度筛查（预测/参考时长比 <0.25 或 >4，**只用于异常定位，不是根因判断**）分别
  标出 DAMIDAMI 43、预言 75、不安 16、提瓦特 8 个区间；详细条目留在本地 JSON。

## 混合语言路由：配对消融（只比较新增匹配区间）

路由开/关均在同一源码、音频、默认权重和 production 配置上重新运行。两种设置都匹配到的
同一参考单元集合误差完全相同；路由影响的是某些行是否能获得模型时间，而非改善共同单元：

| 歌曲 | on/off 共同区间 | 共同 start/end MAE | on 新增区间及误差 | off 独有区间及误差 |
|---|---:|---:|---:|---:|
| 不安灵魂收容所 | 296 / 296 | .172 / .156s | 87；start/end .426/.403s，任一边界 >500ms：41/87 (47.1%) | 12；.791/.696s，>500ms：9/12 (75.0%) |
| 提瓦特民谣 | 382 / 382 | .117 / .118s | 15；start/end .674/.633s，>500ms：7/15 (46.7%) | 0 |

路由确实增加了与参考文本匹配的预测范围（尤其不安灵魂收容所），但新增区间误差并不小；
共同区间没有精度变化。故证据支持“路由增加覆盖”，**不足以宣称路由提升精度**。Teyvat
新增 15 个以英文模型路由的参考区间误差较大，且仍有拉丁歌词回退。不能只看 failed 数减少。

## 必须回答的问题

1. **四份 TTML 是否与本地音频同版？** 元数据歌曲/平台 ID 对应，但本地缺 ISRC；版本和锚点
   尚待人耳确认。现为 provisional，不能回答“已确认同版”。DAMIDAMI 时长差 16.477s，差异
   值得优先查验。没有按 AutoSync 预测校正偏移。
2. **真实可比时间单元多少？** TTML 主唱 429/485/434/469。排除人工试听保留行后，文本
   可匹配参考单元为 358/416、420/464、385/414、422/445；公共边界误差区间 n 为
   315/320/383/397。不可比项及原因在本地 detail。
3. **每首起止误差？** 见主表与边界分布表（均为同版确认前、零偏移暂定值）。
4. **中文还是英文更准确？** 这四首的候选数据里中文更好：不安/提瓦特 start MAE .230/.138s，
   英文 DAMIDAMI/预言 .317/.955s；但歌曲/版本及编曲不同，不能据此推断语言因果。
5. **路由提高了时间精度吗？** 没有改善共同区间；扩大覆盖，但新增样本 MAE .426/.403s 和
   .674/.633s，并存在明显 >500ms 错误。总体是覆盖收益，不是已证实的精度收益。
6. **中/英文也有严重放行吗？** 是。未安 >500ms 19.1%、>1s 2.3%；提瓦特 3.5%/1.5%；
   DAMIDAMI 22.5%/8.9%；预言 58.4%/39.7%。并且质量门未启用，无可靠状态可供误放统计。
7. **离 AMLL 人工打轴多远？** 候选对比范围很不均：提瓦特公共区间 MAE 约 0.14s；预言约
   0.9–1.0s，P90 约 2.2–2.6s。仅有同版人工听音确认后才能作为有效差距结论。
8. **是否足以进入 Android ONNX 原型？** 这些结果**不支持声称精度已达到人工打轴级**；
   Prophecy 与路由新增英文片段的严重误差仍高。同版核验、错误放行审计、ONNX 量化重测之前，
   不应以该评测作为生产逐字高亮精度验收通过。

## 复现与数据隔离

```bash
# 固定上游 SHA 的参考文件已在 ignored experiments/amll_reference/
.venv/bin/python benchmarks/amll_ttml_eval.py --prepare-suite .
# 人工检查 listen.html / 填写 version_audit.json 后再解释为同版结果
.venv/bin/python benchmarks/amll_ttml_eval.py --evaluate-suite .
.venv/bin/python -m pytest tests/test_amll_ttml_eval.py -q
```

四份原始 TTML、音频、LRC、完整 AutoSync 结果、试听 clips、详细歌词级比较均在
`experiments/amll_reference/`、`Test/`、`experiments/amll_results/`，均 gitignore。
公开仓库仅提交解析/匹配实现、无歌词合成测试和本汇总；**不提交 AMLL 时间轴、歌词文本、音频或
完整逐单元结果**。AMLL 只用于独立评分/诊断；未参与模型训练、阈值/路由优化或预测时间修正。
