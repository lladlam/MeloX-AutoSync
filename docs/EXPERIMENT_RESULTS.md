# 实验记录（EXPERIMENT_RESULTS）

> 所有数字来自本仓库**实际运行**的代码。未完成项明确标注，绝不伪造。
> 关键回归：V0.1/V0.2 的评测存在**参考泄漏**，V0.3 已修正（见 §0）。
> 原始报告：`experiments/reports/*.json`（含逐样本 `segments`、失败样本、`by_singer`/`by_song`/`by_technique`）。

## 0. P0：评测方法审计与修正（最重要）

**发现**：V0.2 的 `singing_eval.py` 用人工标注的**首/末字边界**作为行窗口（`start=ref[0].start`, `end=ref[-1].end`），
该窗口同时用于裁剪、模型对齐与启发式均分——这是**参考泄漏**，会让所有引擎在 oracle 条件下被高估。

**修正**：
- 新增 **`lrc_only` 盲评**模式：只使用 音频 + 歌词文本 + LRC 行起始时间（GTSinger 无真实 LRC，故行起始模拟为 `0.0`；可用 `--lrc-onset energy` 用纯音频能量估计）。
- 保留 **`oracle`** 模式（使用标注跨度），仅用于声学算法研究，**单独报告、绝不混合**。
- 所有裁剪/对齐/启发式只依赖 `line_window()` 的盲窗口；Ground Truth 只在 `metrics.score()` 使用（回归测试 `tests/test_eval_modes.py` 断言 `lrc_only` 忽略参考边界）。
- 修复 `accompaniment_eval.py` 把 `model` 与 `model+energy` 混合汇总的缺陷（现按 `(variant, engine)` 分别统计）。
- 评测新增：**覆盖率、漏匹配率、额外单元、分段错误率、不确定边界比例**，并保留失败样本。

## 1. 数据与条件

- 评测集：GTSinger（CC BY-NC-SA 4.0）**96 段**，2 位歌手 × 3 技巧 × 多首歌曲：
  - en: EN-Alto-1 / EN-Tenor-1（Vibrato/Breathy/Glissando）30 段 / 380 词
  - ja: JA-Soprano-1 / JA-Tenor-1（Vibrato/Glissando/Control）30 段 / 570 字
  - zh: ZH-Alto-1 / ZH-Tenor-1（Vibrato/Breathy/Glissando）36 段 / 482 字
- 参考粒度：en=词，zh/ja=字。按歌手/歌曲隔离（本集**不参与任何训练**）。
- 引擎：`heuristic` / `model`（V0.1）/ `model+energy`（V0.2）/ `model+onset`（新增，起始回吸）/ `model+reseg`（新增，能量分段重对齐）。

## 4. 日语诊断（P1）

报告：`experiments/reports/diagnosis_ja.json`（30 段）。

- **CTC 转写 CER：全部 0.687**；塌缩段 0.643，非塌缩段 0.726 —— **即使不塌缩，模型转写也是错的**。
- 塌缩（不可行）计数：`lrc 14/30`、`oracle 15/30`、`energy_trim 13/30` → **窗口/裁剪几乎不影响**（14→13）。
- 多字符 token：98/466（21%）→ 这些单元标记 `uncertain`（不做精确切分）。
- 按歌手：JA-Soprano-1 12/24 塌缩；JA-Tenor-1 4/6 塌缩。
- 替代模型：`japanese-wav2vec2-large-rs35kh`（1.2 GB）**更差**：覆盖率 0.353、失败率 **63.3%**。

**结论**：日语失败是**声学模型与歌声域的失配**，不是窗口/歌词处理/对齐算法问题；加大模型无益。
`model+reseg` 仅在 oracle 下把失败率从 46.7% 降到 33.3%（覆盖 0.528→0.652），但盲评覆盖仍 0.507、误差 ~1.27 s，**不构成可用改进**。

## 5. 英文起始分析（P2）

报告：`experiments/reports/diagnosis_en.json`（30 段）。

- 无塌缩（max span ≤ 0.03）。CTC 转写 CER 中位 0.305（明显好于日文）。
- 盲窗口签名偏差：**start +0.176 s（偏晚）**、end −0.107 s（偏早）。
- 针对「偏晚」尝试 **start 回吸（`model+onset`）**：en **变差**（0.138→0.207），zh 仅微变（0.141→0.138）。
  → 与 V0.2「前向吸附被否决」一致：**能量边界吸附不能稳定改善起始**。
- **大模型 `wav2vec2-large-960h` 无益**：en sMAE 0.138→0.156、eMAE 0.114→0.130（更差且 3× 体积）。
- `model+reseg` 对 en 有害（0.138→0.435）：按能量段落比例切分歌词是错误的。

**结论**：英文起始在本轮**没有得到稳定改善**；当前字符 CTC 已是可用水平，启发式/分段/大模型均无正收益。

## 8. 失败样本（保留）

- 日文 14/30 塌缩段（如 `时雨`）在报告 `singing_ja.json` 的 `segments[*].engines[*][*].model.error` 中，含 `InfeasibleAlignmentError: ... collapsed: one token spans NN% of the audio`；`metrics` 的 `missed`/`extra` 列出未匹配单元。
- 未塌缩日文段仍以 ~1 s 误差对齐（见 §4），未做伪造修正。

## 9. 五个问题的回答

1. **中文在真实 LRC 下是否仍明显优于启发式？** 是。`lrc_only`：sMAE 0.141 vs 0.543（约 3.8×），eMAE 0.198 vs 0.552，覆盖 100%。
2. **日语失败是模型、算法还是窗口？** **模型（歌声域失配）**。CER 0.687、非塌缩段 0.726、能量裁剪仅把塌缩 14→13、大模型更差。
3. **英文起始能否稳定改善？** **本轮否**。回吸、能量吸附、大模型、分段均无正收益；当前 0.138 s 已较好。
4. **最值得移植 Android 的模型？** **中文 `fa-zh`**（最小 151 MB、最准、盲评与 oracle 一致）。英文 `wav2vec2-base-960h` 次之（378 MB，盲评 0.138 s）；**不要**用 large。
5. **需要放弃的？** 日文 reazon 语音模型（含 large）用于歌声、`model+reseg`（能量分段重对齐）、`model+onset`（能量起始吸附）。
