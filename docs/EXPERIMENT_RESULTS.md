## 2. V0.2 歌声评测（真实 GTSinger，含精确边界）

数据集与许可见 `docs/SINGING_EVAL.md`。数据：42 段 a-cappella，覆盖 vibrato / glissando / control 与长拖音。
参考粒度：英文=词，中文/日文=字。

### 2.1 三引擎对比（micro-average，全部匹配样本 + 失败样本统计）

| 语言 | 引擎 | 匹配数 | 覆盖率 | 漏匹配率 | start MAE | start P90 | end MAE | end P90 | 失败段 |
|---|---|---|---|---|---|---|---|---|---|
| **en** | heuristic | 26 | 1.000 | 0.000 | 0.326 | 0.686 | 0.309 | 0.686 | 0 |
| en | model (V0.1) | 26 | 1.000 | 0.000 | 0.367 | 1.000 | 0.150 | 0.246 | 0 |
| en | model+energy (V0.2) | 26 | 1.000 | 0.000 | 0.367 | 1.000 | **0.137** | 0.246 | 0 |
| **ja** | heuristic | 368 | 1.000 | 0.000 | 1.204 | 2.998 | 1.244 | 3.107 | 0 |
| ja | model (V0.1) | 180 | **0.489** | **0.511** | 0.579 | 1.672 | 0.606 | 1.818 | **9** |
| ja | model+energy (V0.2) | 180 | 0.489 | 0.511 | 0.579 | 1.672 | 0.606 | 1.818 | 9 |
| **zh** | heuristic | 220 | 1.000 | 0.000 | 0.539 | 1.319 | 0.556 | 1.366 | 0 |
| zh | model (V0.1) | 220 | 1.000 | 0.000 | **0.151** | **0.232** | 0.198 | 0.446 | 0 |
| zh | model+energy (V0.2) | 220 | 1.000 | 0.000 | 0.151 | 0.232 | **0.163** | 0.448 | 0 |

**解读（诚实）**

* **中文**：`fa-zh` 明显优于启发式（start 0.151 vs 0.539），且 100% 覆盖。
* **英文**：模型的**结束**边界优于启发式（0.150 vs 0.309），但**起始**边界反而略差（0.367 vs 0.326，P90 1.0 s）。英文语音模型（wav2vec2-960h）对拖长音的起音定位不稳定。
* **日文**：模型在 9/18 段上**拒绝输出**（见 §3 失败样本），有效段的精度（0.579）远好于启发式（1.204）；但覆盖率仅 0.489——即约一半歌声无法可靠对齐。
* **V0.2 能量细化**：稳定地**改善结束**边界（en 0.150→0.137；zh 0.198→0.163），对起始无影响，对日文无影响。收益有限但方向一致、无副作用。

## 3. 失败样本（必须保留）

### 3.1 日文：CTC 对齐塌缩（9 段）

诊断（`时雨/Control_Group/0000`）：模型 CTC 转写为
`水の馬にしでが思いいでつり行く時が`，而参考是 `いつのまに失くしてた思い出移り行`。
声学后验与歌词完全不符，Viterbi 退化为**单个 token 占据 56–81% 的音频**，其余 token 挤在末尾。

例（段内字符时间）：

```
い  ref 1.20-1.29   pred 0.00-8.06   (err 7.09s)   <- 一个 token 占据 8 秒
つ  ref 1.29-1.52   pred 8.06-8.16
...
```

系统的处理：`forced_align` 检测到塌缩（单 token 占比 > 50%），`Alignment.feasible=False`，
适配器抛 `InfeasibleAlignmentError`，该行标记为 **failed**，**不输出伪造时间**。
这正是 V0.2「检测异常对齐」要求的落地。

失败段 ID 与原因保存在报告的 `segments[*].engines.model.error`。

### 3.2 英文：起始 P90 = 1.0 s

英文 model 的 word 起始有约 10% 的边界误差 ~1 s，源于拖长音的起音被模型放到静音区。
V0.2 尝试了「起始吸附到有声起点」，结果**使误差变大**（见 §4），故默认关闭。

## 4. 被否决的改进（负结果，如实记录）

| 改进 | en start MAE | zh start MAE | 结论 |

## 5. 伴奏混音实验（受控，非真实混音）

无法获得真实带伴奏且可授权的歌声（MIR-1K 下载链接 404；GTSinger 为 a-cappella）。
因此使用**从该段自带乐谱合成**的伴奏床（无第三方音频，许可安全），与干净人声混合，对比误差。

| 语言 | 变体 | start MAE | end MAE | 覆盖率 | 失败 |
|---|---|---|---|---|---|
| zh | clean | 0.129 | 0.164 | 1.000 | 0 |
| zh | mix +0 dB | 0.132 | 0.181 | 1.000 | 0 |
| zh | mix −6 dB | 0.132 | 0.180 | 1.000 | 0 |
| en | clean | 0.367 | 0.144 | 1.000 | 0 |
| en | mix +0 dB | 0.355 | 0.154 | 1.000 | 0 |

**限制（重要）**：合成伴奏床跟随旋律，掩蔽效应有限；**真实商业混音下的误差仍未验证**。
不能把本表当作「真实歌曲伴奏影响」的结论。

## 7. V0.2 代码改动如何影响结果

1. **CTC 可行性/塌缩检测**：日文 9 段由「输出垃圾」变为「报告失败」，覆盖率从 1.000（假）降到 0.489（真）。
2. **日文 token→原文映射**：逐 token 还原原文字符，多字符 token 标记 `uncertain=True`，并校验原文可重建（`check_reconstruction`）。
3. **评测器**：新增覆盖率、漏匹配率、额外单元、分段错误率与失败样本；不再只统计成功匹配。
4. **能量细化**：end MAE 改善（en/zh），起始吸附被否决。
