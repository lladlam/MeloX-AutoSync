# 日语长音 / 错位分析（JAPANESE_LONG_VOWEL_ANALYSIS） — V0.5 §2

> 数据：GTSinger 日语 30 段，`lrc_only` 盲评，评分器 `benchmarks/metrics.py`。
> 脚本：`benchmarks/ja_long_vowel_analysis.py`；原始输出 `experiments/reports/ja_long_vowel.json`。
> 所有选择均基于**声音或事先固定的规则**，禁止依据 Ground Truth 挑选模型。

|---|---|---|---|---|---|
| 歩 | ある | aru | 0.00–1.00 | 0.05–0.99 | 0.06–0.62 |

## 2. 主要原因（结论）

**不是单纯的「长音归属」问题，而是「句子内部非歌词区间（`<AP>`/`<SP>`）被强行对齐」问题。**

证据：

1. 参考在 `歩`(0–1.00) 与 `こ`(3.18) 之间有 **1.0–3.18 s 的 `<AP>`**。
2. 该 `<AP>` 区间**并非静音**：实测 RMS ≈ **−16.3 dB**，比 `歩`(−20.9 dB)、`こ`(−18.0 dB) 还响
   —— 即区间内仍有音频能量（伴奏/环境声/气息），只是没有歌词。
3. 我们的音素序列（由歌词 G2P 得到）**不含内部 `pau`**，HSMM/CTC 只能把歌词音素拉伸覆盖整段音频，
   于是 `こ` 被提前到约 1.0 s。
4. **29/30** 个日语段都存在 >0.5 s 的内部 `<AP>`/`<SP>`（最长 **4.36 s**）。

分区间指标（按段是否含内部停顿划分，HuBERT）：

| 分组 | start MAE | start P90 |
|---|---|---|
| 无内部停顿段 | 0.119 | 0.242 |
| 含内部停顿段 | 0.373 | 1.169 |

即：**内部非歌词区间是日语误差的主要来源**，而不是「一个长音被记到相邻文字」。

## 3. 本轮同时修复的两个真实缺陷

1. **HuBERT 音素→文字索引偏移（P0）**：适配器从 `cursor=0` 建索引，而完整音素序列带前导 `pau`，
   导致每个字的音素区间整体错位一格。修复后（显式 `locate_inner_offset` + 校验）：
   HuBERT sMAE **0.643 → 0.380 → 0.365**（叠加映射修复），sP90 1.399 → 1.121。
2. **G2P 文字↔假名映射错误**：整串 DP 在「汉字读长 + 助词音变」时出现欠定错误
   （如 `私→わ, は→た`）。改用 MeCab **词级上下文读音**（`pyopenjtalk.run_frontend` 的 `pron`，
   `は→ワ`）后，`私は元気` 正确映射为 `私→わたし, は→わ, 元→げ, 気→んき`。

## 4. 交叉校验（ensemble，规则事先固定）

规则：逐字取 pyshiro 与 HuBERT 两个**独立模型**预测的均值（不作 GT 选择）。结果：

| 引擎 | 覆盖 | sMAE | s中位 | sP90 | eMAE |
|---|---|---|---|---|---|
| pyshiro v2 | 1.000 | 0.611 | 0.105 | 2.184 | 0.608 |
| **HuBERT（修正后）** | 1.000 | **0.365** | **0.063** | **1.121** | 0.622 |
| ensemble（均值） | 1.000 | 0.456 | 0.091 | 1.367 | 0.546 |

**结论**：单模型（修正后的 HuBERT）在起始指标上已优于 ensemble；ensemble 未提供额外收益，
故**不作为正式算法**（保留为对照）。

## 5. 尝试过但**未**采用的方案

- **整行平移**：禁用（会掩盖错误、非声学依据）。
- **仅优化 `さんぽ` 的规则**：禁用（过拟合单曲）。
- **按能量分段 + 文本按比例切分**（V0.3 `reseg`）：在含内部 `<AP>` 的段落上会切错歌词位置，
  整体退化（见 `EXPERIMENT_RESULTS.md`）。
- **ensemble 均值**：不如修正后的 HuBERT，见 §4。

## 6. 下一步（有证据）

内部非歌词区间需要**暂停感知对齐**：在声学层检测「非歌词帧」（例如 CTC blank 占优、或
音素后验低的连续帧），并在音素序列中插入相应数量的 `pau`，使模型能把非歌词区间分配给暂停，
而不是拉伸歌词音素。该方向本轮**未实现**（避免在缺乏验证的情况下引入回归），列为明确的下一步，
必须在同一 `lrc_only` 协议下验证整体不退化后才可采用。
