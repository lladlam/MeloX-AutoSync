# 已知限制与未解决问题（KNOWN_LIMITATIONS）

> 本文件是诚实清单：哪些没做完、哪些不可信、哪些有风险。

## 1. 未完成的验证（最重要）

- **实验 C（清晰歌声）未执行**：环境中没有合法授权的歌声/人声素材。合成 TTS 语音**不能**代表歌唱的拖音、颤音、连唱。
- **实验 D（原曲混音 vs 干净人声）未执行**：没有可合法处理的带伴奏歌曲。
- **无歌声的人工标注 ground truth**：因此**没有任何歌声上的误差数字**。凡涉及歌声的结论均为推断，不是实测。

## 2. 结束时间系统性偏早

- 英文合成样本：end MAE ≈ 0.39 s（起始 MAE 仅 0.067 s）。
- 原因分析：wav2vec2 字符 CTC 把词尾衰减段归为 blank；espeak 合成语音与 LibriSpeech 域差异放大了这一现象。
- 真实人类语音（LibriSpeech）上时间覆盖合理，说明**域匹配比算法本身影响更大**。
- 尚未实现「基于音频能量/VAD 的尾部延展」修正。

## 3. 合成语音评估的固有偏差

- espeak 合成与真人训练域差异大：日语合成样本置信度极低（log-prob ≈ −13），基本不可用；中文合成存在 p90 > 1 s 的离群。
- 因此合成数据上的误差**只能作为相对比较**（如模型 vs 启发式），**不能当作真实歌曲的绝对精度**。

## 4. 算法与流程限制

- **按行独立对齐**：每行单独裁剪窗口后对齐，行与行之间不做全局约束。跨行拖音、行间粘连可能被切断。
- **末行窗口延伸到音频末尾**：若歌曲有很长器乐尾奏，会产生大量 blank 帧（结果正确但浪费计算）。
- **重复字符/同字连续**：CTC 对相邻相同 token 需要 blank 分隔，极端情况下可能退化（已由单测覆盖基本情形）。
- **未利用增强 LRC 的 `<mm:ss>` 分段**：解析器已保留 `segments`，但当前对齐未以其为先验。
- **英文单元文本**：以原文词为主，但标点/大小写映射在数量不匹配时回退到规范化文本。
- **非流式、非增量**：整行一次处理，长行帧数 × 状态数可能较大（本样本无压力）。
- **启发式结果显式标注**：`--engine heuristic` 或 `--fallback heuristic` 输出 `source="heuristic"`，不会被伪装成模型结果。

## 5. 工程与依赖限制

- **内存**：CPU 峰值 0.86–1.08 GB，对低内存设备偏高（见 Android 可行性）。
- **中文依赖重**：`funasr` extra 引入 scikit-learn / sentencepiece / oss2 / librosa 等，安装体积与冲突风险高于 en/ja。
- **中文许可证**：`funasr/fa-zh` 为 FunASR Model License（other），商业分发前须复核。
- **日文词表粒度**：一个 token 可能是多字词（如 `世界`、`あり`），输出单元并非严格「单字」，需要下游按 `raw` 处理。
- **未做模型量化**：当前均为 FP32。

## 6. 数据与合规

- 所有测试音频：LibriSpeech 官方样例、FLEURS 公开样本、espeak 合成——均为**非商业歌曲音频**。
- 未上传任何未授权商业歌曲。
- 权重不进 Git（`models/` 已忽略）。
