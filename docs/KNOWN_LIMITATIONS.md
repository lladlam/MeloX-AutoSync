# 已知限制与未解决问题（KNOWN_LIMITATIONS）

> 诚实清单，对应 V0.3。数字见 `docs/EXPERIMENT_RESULTS.md`，验收见 `docs/ACCEPTANCE.md`。

## 0. 已修复（V0.3）

- **评测参考泄漏**：V0.2 用人工首/末字边界作为行窗口（裁剪+启发式均分），高估了所有引擎。
  V0.3 引入 `lrc_only` 盲评（只看音频+歌词文本+LRC 行起始），并保留 `oracle` 仅作研究；二者分开报告。
- **伴奏聚合缺陷**：`accompaniment_eval.py` 曾把 `model` 与 `model+energy` 混入同一均线，已按引擎分开。

## 1. 评测方法本身的限制

- GTSinger 片段**没有真实 LRC**，`lrc_only` 的行起始被模拟为 `0.0`（可用 `--lrc-onset energy` 估）。
  真实歌曲的 LRC 行起始通常更贴近人声，本盲评偏保守。
- 评测是**段级**（每段一句歌词），不是整曲多行时间轴，未验证行间衔接与长时轴漂移。
- 每语言仅 2 位歌手、有限曲目；不能代表全部唱法（rap/快速连唱/强颤音未覆盖）。

## 2. 各语言结论与限制

- **中文（`fa-zh`）**：`lrc_only` 明显优于启发式（sMAE 0.141 vs 0.543），覆盖 100%；
  end P90 0.511 略超验收目标 0.50。许可证为 FunASR Model License，商用需复核。
- **英文（`wav2vec2-base-960h`）**：`lrc_only` 全项达标（sMAE 0.138/eMAE 0.114）。
  但**起始时间未获稳定改善**：能量回吸、前向吸附、large 模型、能量分段均无正收益。
- **日文（`reazon-*-base-rs35kh`）**：**不可用**（语音模型唱歌失败）。V0.4 起改用**歌声模型**：
  pyshiro 覆盖率 1.000、失败率 0%、起始中位 ~0.10 s；V0.5 修正 HuBERT 索引偏移后，
  **HuBERT 音素 CTC 起始 sMAE 0.365、中位 0.063、P90 1.121，为当前最优**。
  **但仍未达 MAE ≤200ms**（见下条根因）。详见 `docs/JAPANESE_MODEL_COMPARISON.md`。

## 0b. V0.5 根因：句子内部非歌词区间

- **29/30** 个日语段含 >0.5 s 的内部 `<AP>`/`<SP>`（最长 4.36 s），且这些区间**并非静音**
  （实测比人声还响，含伴奏/环境声）。
- 我们的音素序列不含内部 `pau`，模型只能把歌词音素拉伸覆盖非歌词区间 → 起始误差的主要来源。
- 该问题本轮**未修复**（暂停感知对齐列为下一步），不夸大 pyshiro/HuBERT 的现有精度。
- 另：V0.4 的 HuBERT 精度数字因**索引偏移缺陷**作废，V0.5 已修正并重测。

## 3. 被否决的方案（负结果，保留证据）

| 方案 | 结果 |
|---|---|
| 能量边界前向吸附（V0.2） | en/zh 起始更差 |
| 能量起始回吸 `model+onset`（V0.3） | en 0.138→0.207，zh 仅 0.141→0.138（不具一致性） |
| 能量分段重对齐 `model+reseg`（V0.3） | en 0.138→0.435，zh 0.141→1.064（严重变差）；仅 ja-oracle 覆盖略升 |
| 英文 large 模型（`wav2vec2-large-960h`） | en 更差（0.138→0.156）且 3× 体积 |
| 日文 large 模型（`japanese-wav2vec2-large`） | 失败率 46.7%→63.3% |

- **歌声域模型未引入**：本轮只测试了语音模型与加大规模，未引入/微调歌声专用模型。
- **日文与英文的起始问题未解决**（英文起始未改善；日文整体不可用）。
