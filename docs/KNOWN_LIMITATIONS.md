# 已知限制与未解决问题（KNOWN_LIMITATIONS）

> 诚实清单，对应 V0.3。数字见 `docs/EXPERIMENT_RESULTS.md`，验收见 `docs/ACCEPTANCE.md`。

## 0. 已修复（V0.3）

- **评测参考泄漏**：V0.2 用人工首/末字边界作为行窗口（裁剪+启发式均分），高估了所有引擎。
  V0.3 引入 `lrc_only` 盲评（只看音频+歌词文本+LRC 行起始），并保留 `oracle` 仅作研究；二者分开报告。
- **伴奏聚合缺陷**：`accompaniment_eval.py` 曾把 `model` 与 `model+energy` 混入同一均线，已按引擎分开。

## 1. 评测方法本身的限制

- GTSinger 片段**没有真实 LRC**，`lrc_only` 的行起始被模拟为 `0.0`（可用 `--lrc-onset energy` 估）。
  真实歌曲的 LRC 行起始通常更贴近人声，本盲评偏保守。
- 评测是**段级**（每段一句歌词），不是整曲多行时间轴，未验证行间衔接与长时轴漂移。
- 每语言仅 2 位歌手、有限曲目；不能代表全部唱法（rap/快速连唱/强颤音未覆盖）。

## 2. 各语言结论与限制

- **中文（`fa-zh`）**：`lrc_only` 明显优于启发式（sMAE 0.141 vs 0.543），覆盖 100%；
  end P90 0.511 略超验收目标 0.50。许可证为 FunASR Model License，商用需复核。
- **英文（`wav2vec2-base-960h`）**：`lrc_only` 全项达标（sMAE 0.138/eMAE 0.114）。
  但**起始时间未获稳定改善**：能量回吸、前向吸附、large 模型、能量分段均无正收益。
- **日文（`reazon-*-base-rs35kh`）**：**不可用**（语音模型唱歌失败）。V0.4 起改用**歌声模型**：
  pyshiro 覆盖率 1.000、失败率 0%、起始中位 ~0.10 s；V0.5 修正 HuBERT 索引偏移后，
  **HuBERT 音素 CTC 起始 sMAE 0.365、中位 0.063、P90 1.121，为当前最优**。
  **但仍未达 MAE ≤200ms**（见下条根因）。详见 `docs/JAPANESE_MODEL_COMPARISON.md`。

## 0b. V0.5 根因：句子内部非歌词区间

- **29/30** 个日语段含 >0.5 s 的内部 `<AP>`/`<SP>`（最长 4.36 s），且这些区间**并非静音**
  （实测比人声还响，含伴奏/环境声）。
- 我们的音素序列不含内部 `pau`，模型只能把歌词音素拉伸覆盖非歌词区间 → 起始误差的主要来源。
- 该问题本轮**未修复**（暂停感知对齐列为下一步），不夸大 pyshiro/HuBERT 的现有精度。
- 另：V0.4 的 HuBERT 精度数字因**索引偏移缺陷**作废，V0.5 已修正并重测。

## 0c. V0.6 更正：根因是**低声学后验**，不是“缺少内部 pau”

- 统计学验证：corr(start_MAE, 内部停顿) = **−0.09（无关）**；corr(start_MAE, blank 后验) = +0.47、
  corr(start_MAE, 歌词后验) = −0.48。最差段歌词后验仅 0.04–0.09 → **模型无判别力**。
- CTC blank 本就能吸收非歌词时间；V0.5 的 token span 平均仅 **1.4 帧**，并不存在“拉伸覆盖”。
- 真正机制：**多音素汉字**的若干音素落在分散噪声峰上，字符区间被拉大。
- 三种暂停感知方案（blank-aware / optional-pause / gap-state）**均无稳定收益**，
  故 **V0.5 仍为默认算法**；`pau`/`sil` 后验≈0，方案 B 前提不成立。
- 详见 `docs/PAUSE_AWARE_ALIGNMENT.md`。

## 3. 被否决的方案（负结果，保留证据）

| 方案 | 结果 |
|---|---|
| 能量边界前向吸附（V0.2） | en/zh 起始更差 |
| 能量起始回吸 `model+onset`（V0.3） | en 0.138→0.207，zh 仅 0.141→0.138（不具一致性） |

## 6. V0.7 质量门控：结论与保留限制

- **质量门控无法可靠判定**：最佳特征 AUC 0.665、分组 CV 的 F1 仅 0.65–0.67；
  接受 50% 歌词行后严重行率仍 0.47。见 `docs/SELECTIVE_ALIGNMENT_REPORT.md`。
- **严重错误是常态**：行级最大起始误差 >0.5s 的有 27/30，>1.0s 的有 20/30。
- **明显男声偏差**：男高 sMAE ≈1.02 / 6 段全严重；女高 ≈0.24。
- 因此仅采用**保守回退**（FAILED/UNCERTAIN → 整行 LRC），**不宣称**校准后的准确率概率。
- 时间轴本身仍是 V0.5（未改）；质量评估只读。
- 代码审计（V0.7 §8）已修复：`gap_state` 替换 spans 后的陈旧元数据（重算路径得分）、
  `optional_pause` 明确为文档化 no-op、诊断 `.npz` 已从 Git 移除并加入 `.gitignore`。

## 7. V0.8 引擎整合限制

- **日语默认后端改为 HuBERT Phoneme CTC（experimental）**；旧 ReazonSpeech 为可选基线。生产模式默认
  **安全回退**（非 RELIABLE 或未评估 → 整行 LRC），逐字时间需显式 `--mode experimental`。
- **质量门控仍不可靠**：修正交叉验证的特征选择泄漏后，LOSO F1 降至 **0.58**、LOSO-song **0.59**
  （V0.7 的 0.65/0.67 偏乐观，已作废）。真实案例中 `さんぽ` 被**误判为 reliable**（false accept）。
- 因此门控**仅用于保守回退**，不作为精度保证。
- **原始 LRC 时间与模型时间已彻底分离**（见 `docs/LRC_FALLBACK_CONTRACT.md`）；回退使用原始 LRC。
- **真实整曲**（多行 + 伴奏 + 长时轴）：V0.8 时未完成，**V0.9 已用用户自备本地授权素材完成**
  （2 首整曲、各 73 行；见 `docs/CLI_END_TO_END.md` §7），通过行守/单调/窗口合法性校验。

## 8. V0.9 非演唱行识别限制

- 分类基于**文本规则**（中/日/英常见署名与 cue），不删除任何原始行；不确定时给 `UNKNOWN`
  （同样不参与对齐，按原始时间整行展示）。
- 规则是**保守**的：真正的歌词若恰好以署名关键词开头（如 `作詞は君のためじゃない`）仍判为 `SINGING`；
  但极少数非常规署名格式（如 `作詞米津玄師` 无分隔符单关键词）会被当作歌词并对齐，
  目前仅当一行内出现 ≥2 个署名关键词时才判 `UNKNOWN`。
- 未做基于音频的判定（例如“这行没有演唱”），因此**前奏/尾奏中的器乐行若没有 cue 文字**仍会进入对齐。
- 真实整曲验证：**V0.9 已用用户自备本地授权素材完成**（2 首整曲、73 行/首；见 `docs/CLI_END_TO_END.md` §7），
  通过合法性校验；但素材未提交（版权）。
- **新发现**：中文歌曲中的拉丁字母行（如 `(Bora sana, Bora sana)`）在 zh 适配器下会失败
  （`normalize_cjk` 清空文本），已如实报告为 `failed` 并整行回退，不伪造时间。
