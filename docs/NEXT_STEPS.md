# 下一阶段优先级（NEXT_STEPS）

> 基于 V0.3 盲评（`lrc_only`）实测。原则：先解决阻塞问题，不盲目扩架构。

## P0 — 整曲真实 LRC 验证

1. 用真实歌曲（含完整 LRC：多行、间奏、时间轴）跑 `autosync align`，并在**整曲**上评估。
2. 段级盲评已达标的是 zh/en；需确认整曲下不漂移（行间衔接、长时轴）。

## P1 — 引入歌声域声学模型（解决日文、改善起始）

1. **V0.4 已完成**：日语换用 **pyshiro**（歌声 HSMM），覆盖率 1.000、失败率 0%、中位 ~0.10 s；
   **V0.5 修正** HuBERT 音素 CTC 索引偏移后，其起始指标（sMAE 0.365 / 中位 0.063 / P90 1.121）**最优**，
   且**代码与权重均可再分发**（Apache-2.0），应作为默认方案。
2. **V0.6 已排除“缺少内部 pau”假设**：暂停感知三方案（blank-aware / optional-pause / gap-state）
   **均无稳定收益**（`docs/PAUSE_AWARE_ALIGNMENT.md`）。根因是**部分段落声学后验无信息**
   （blank≈1，歌词后验 0.04–0.09），对齐算法无法弥补。
3. **下一步（有证据）**：
   - **保守置信度门控**：段落级最大歌词后验过低时标记 `uncertain` 并回退，而非输出看似可信的时间；
   - **引入歌声域更强的模型或域适配**（按歌手/歌曲隔离，许可清晰的数据），这是降低极端错误的唯一途径；
   - 男高音段落单独评估（当前 HuBERT 男高 sMAE ≈0.95 vs 女高 ≈0.23）。
4. pyshiro 权重许可不明 → 不进入公开语言包（见 `docs/LICENSE_AUDIT.md`）。
5. TIFA 端到端仍未跑通（磁盘配额），可后续补做。

## P2 — 起始时间（在歌声域模型之后再谈）

- 已知：能量吸附/回吸、分段、大模型均无收益（见 `KNOWN_LIMITATIONS.md` §3）。
- 下一步方向：**音素级对齐**或**起音 onset 检测**，必须**同时报告 start 与 end**。

## P3 — 扩大评测

- 增加歌手数、音域、歌曲与技巧（rap/连唱/强颤音），保持 **singer/song 隔离**。
- 引入真实伴奏混音（合法授权）以替代合成床。

## P4 — Android 移植

- 首选 **中文 `fa-zh`**，其次英文 `wav2vec2-base-960h`（见 `ANDROID_FEASIBILITY.md`）。
- 先做 ONNX + int8 量化，量化后**重跑本盲评**确认精度损失。
- 日文**暂缓**直至有可用歌声域模型。

## 需要你（用户）提供

- 至少一首**有授权**的完整歌曲（含 LRC、最好含伴奏轨与人工标注），用于整曲验收。
- 是否允许用 GTSinger 训练集做**非商业**歌声域适配实验。
- 中文模型的商业使用意向（确认 FunASR Model License）。
