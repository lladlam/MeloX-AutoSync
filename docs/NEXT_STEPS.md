# 下一阶段优先级（NEXT_STEPS）

> 基于 V0.3 盲评（`lrc_only`）实测。原则：先解决阻塞问题，不盲目扩架构。

## P0 — 整曲真实 LRC 验证

1. 用真实歌曲（含完整 LRC：多行、间奏、时间轴）跑 `autosync align`，并在**整曲**上评估。
2. 段级盲评已达标的是 zh/en；需确认整曲下不漂移（行间衔接、长时轴）。

## P1 — 引入歌声域声学模型（解决日文、改善起始）

1. 在 **GTSinger 训练集**（CC BY-NC-SA，非商业）上做**轻量域适配**，严格遵守
   **按歌手/歌曲隔离**的划分，避免与评测泄漏。
2. 评估面向歌声的开源模型/对齐器（含音素级），要求：按语言独立、体积可控、许可证允许。
3. 日文优先：当前语音模型不可用；需歌声域模型或放弃日文。

## P2 — 起始时间（在歌声域模型之后再谈）

- 已知：能量吸附/回吸、分段、大模型均无收益（见 `KNOWN_LIMITATIONS.md` §3）。
- 下一步方向：**音素级对齐**或**起音 onset 检测**，必须**同时报告 start 与 end**。

## P3 — 扩大评测

- 增加歌手数、音域、歌曲与技巧（rap/连唱/强颤音），保持 **singer/song 隔离**。
- 引入真实伴奏混音（合法授权）以替代合成床。

## P4 — Android 移植

- 首选 **中文 `fa-zh`**，其次英文 `wav2vec2-base-960h`（见 `ANDROID_FEASIBILITY.md`）。
- 先做 ONNX + int8 量化，量化后**重跑本盲评**确认精度损失。
- 日文**暂缓**直至有可用歌声域模型。

## 需要你（用户）提供

- 至少一首**有授权**的完整歌曲（含 LRC、最好含伴奏轨与人工标注），用于整曲验收。
- 是否允许用 GTSinger 训练集做**非商业**歌声域适配实验。
- 中文模型的商业使用意向（确认 FunASR Model License）。
