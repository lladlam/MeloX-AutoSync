# 下一阶段优先级（NEXT_STEPS）

> 原则：先解决实际阻塞问题，不盲目扩大架构。基于 V0.2 的歌声实测结果。

## P0 — 让「歌声」真正可用

1. **切换/微调更合适的声学模型**。实测日文 reazon 语音模型在歌声上约一半塌缩、英文起音 P90≈1s。可行方向：
   - 用 **GTSinger 训练集**（CC BY-NC-SA，可本地使用）对该语言模型做轻量微调/域适配（本阶段范围外，但可行）。
   - 或引入面向歌声的声学模型（如唱歌专用 CTC），仍按语言独立、小模型原则评估。
2. **真实伴奏混音验证**。寻找可授权、可下载的真实 vocal+accompaniment（如重新获取 MIR-1K，或自录/授权素材），替换 §5 的合成伴奏床，给出真实误差增量。
3. **扩大评测集**：每语言至少 30–50 段，覆盖男/女声、不同歌曲、rap/连唱/强颤音，并加入人工抽检。

## P1 — 精度改进（有更多标注后）

1. **英文起音**：当前起始吸附被否决；改用「音节/音素级对齐 + 起音 onset 检测」而非字符级直推。
2. **日文**：评估字符级日语 CTC 模型（避免音素/子词塌缩），并保留 `uncertain` 映射。
3. **行间全局约束**：处理跨行拖音与连唱。
4. **把 `uncertain` 纳入评分**：报告中单独给出「可精确分割字」的误差，避免把不确定边界计入精度。

## P2 — Android 落地（见 ANDROID_FEASIBILITY.md）

1. en/ja：ONNX 导出 + int8 量化，量化后重跑歌声评测确认精度损失。
2. 中文单独立项。

## P3 — 工具与流程

1. `autosync align` 增加 `--refine energy`（已完成）与可视化对比工具。
2. 把 GTSinger 子集评测接入 CI（需要本地数据时跳过）。

- 是否允许用 GTSinger 训练集做**非商业**域适配实验。
